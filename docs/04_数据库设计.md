# 公司内部内容自动发布平台 — 数据库表设计

## 1. 设计原则

第一阶段保持数据库简单。

建议核心只使用 6 张表：

```text
users
contents
publish_targets
review_records
publish_records
operation_logs
```

不创建复杂权限、角色、部门、版本、标签等表。

角色直接保存在 `users.role`。

分类第一阶段直接保存在 `contents.category`。

---

# 2. users — 用户表

用途：

- 登录
- 用户管理
- 区分管理员和普通员工

字段：

| 字段 | 类型 | 必填 | 说明 |
|---|---|---:|---|
| id | bigint | ✓ | 主键 |
| username | varchar(100) | ✓ | 登录账号，唯一 |
| password_hash | varchar(255) | ✓ | 密码 Hash |
| name | varchar(100) | ✓ | 姓名 |
| role | varchar(20) | ✓ | admin / employee |
| status | varchar(20) | ✓ | active / disabled |
| created_at | datetime | ✓ | 创建时间 |
| updated_at | datetime | ✓ | 更新时间 |
| deleted_at | datetime | - | 逻辑删除时间 |

建议索引：

```text
UNIQUE(username)
INDEX(role)
INDEX(status)
```

---

# 3. contents — 内容表

用途：

保存所有待发布和已发布内容。

字段：

| 字段 | 类型 | 必填 | 说明 |
|---|---|---:|---|
| id | bigint | ✓ | 主键 |
| title | varchar(255) | ✓ | 标题 |
| description | text | - | 简介 |
| category | varchar(100) | - | 分类 |
| content_type | varchar(50) | ✓ | html / dynamic / ppt / pdf / word / excel / image / file |
| source_file_name | varchar(255) | - | 原始文件名 |
| source_file_path | varchar(1000) | - | 原始文件存储路径 |
| content_body | longtext | - | HTML / 动态页面等文本内容 |
| publish_target_id | bigint | - | 发布目标 |
| review_status | varchar(20) | ✓ | draft / pending / approved / rejected |
| publish_status | varchar(20) | ✓ | unpublished / publishing / published / failed |
| reject_reason | text | - | 最近一次驳回原因 |
| view_url | varchar(1000) | - | 发布后的访问 URL |
| published_at | datetime | - | 最近发布时间 |
| created_by | bigint | ✓ | 创建用户 |
| created_at | datetime | ✓ | 创建时间 |
| updated_at | datetime | ✓ | 更新时间 |
| deleted_at | datetime | - | 逻辑删除 |

外键：

```text
created_by → users.id
publish_target_id → publish_targets.id
```

建议索引：

```text
INDEX(created_by)
INDEX(content_type)
INDEX(category)
INDEX(review_status)
INDEX(publish_status)
INDEX(published_at)
INDEX(publish_target_id)
```

第一阶段关键词搜索：

```text
title
description
```

如果数据库支持全文索引，可以后续增加：

```text
FULLTEXT(title, description)
```

---

# 4. publish_targets — 发布目标表

用途：

实现“发布目录可灵活配置”。

字段：

| 字段 | 类型 | 必填 | 说明 |
|---|---|---:|---|
| id | bigint | ✓ | 主键 |
| name | varchar(100) | ✓ | 发布目标名称 |
| content_types | json / text | ✓ | 支持的内容类型 |
| publish_root | varchar(1000) | ✓ | 服务器物理发布根目录 |
| base_url | varchar(1000) | ✓ | 对外访问 URL 根路径 |
| enabled | boolean | ✓ | 是否启用 |
| created_by | bigint | ✓ | 创建管理员 |
| created_at | datetime | ✓ | 创建时间 |
| updated_at | datetime | ✓ | 更新时间 |

示例：

```text
id: 2
name: PPT 发布区
content_types: ["ppt", "pptx"]
publish_root: /data/company-site/presentation/
base_url: https://internal.example.com/presentation/
enabled: true
```

最终路径示例：

```text
publish_root
+ generated_relative_path
```

得到：

```text
/data/company-site/presentation/project-a/index.html
```

最终 URL：

```text
base_url
+ generated_relative_path
```

得到：

```text
https://internal.example.com/presentation/project-a/
```

建议索引：

```text
INDEX(enabled)
```

---

# 5. review_records — 审核记录表

用途：

记录普通员工提交和管理员审核过程。

建议每次提交 / 审核都保留一条记录，避免只在 `contents` 中保存最终状态导致历史丢失。

字段：

| 字段 | 类型 | 必填 | 说明 |
|---|---|---:|---|
| id | bigint | ✓ | 主键 |
| content_id | bigint | ✓ | 内容 ID |
| action | varchar(30) | ✓ | submit / approve / reject |
| from_status | varchar(20) | - | 操作前状态 |
| to_status | varchar(20) | ✓ | 操作后状态 |
| comment | text | - | 审核备注 / 驳回原因 |
| operated_by | bigint | ✓ | 操作人 |
| created_at | datetime | ✓ | 操作时间 |

外键：

```text
content_id → contents.id
operated_by → users.id
```

建议索引：

```text
INDEX(content_id)
INDEX(action)
INDEX(operated_by)
INDEX(created_at)
```

---

# 6. publish_records — 发布记录表

用途：

记录每一次实际发布执行。

发布失败重试时新增记录，不覆盖旧记录。

字段：

| 字段 | 类型 | 必填 | 说明 |
|---|---|---:|---|
| id | bigint | ✓ | 主键 |
| content_id | bigint | ✓ | 内容 |
| publish_target_id | bigint | ✓ | 发布目标 |
| status | varchar(20) | ✓ | publishing / success / failed |
| source_path | varchar(1000) | - | 本次发布源文件 |
| output_path | varchar(1000) | - | 最终服务器发布位置 |
| publish_url | varchar(1000) | - | 最终访问 URL |
| message | text | - | 发布结果说明 |
| error_message | text | - | 失败原因 |
| triggered_by | bigint | ✓ | 触发发布的用户 |
| started_at | datetime | - | 开始时间 |
| finished_at | datetime | - | 完成时间 |
| created_at | datetime | ✓ | 记录创建时间 |

外键：

```text
content_id → contents.id
publish_target_id → publish_targets.id
triggered_by → users.id
```

建议索引：

```text
INDEX(content_id)
INDEX(publish_target_id)
INDEX(status)
INDEX(triggered_by)
INDEX(created_at)
```

---

# 7. operation_logs — 操作日志表

用途：

记录平台中的关键操作。

字段：

| 字段 | 类型 | 必填 | 说明 |
|---|---|---:|---|
| id | bigint | ✓ | 主键 |
| user_id | bigint | - | 操作用户 |
| action | varchar(100) | ✓ | 操作类型 |
| target_type | varchar(50) | - | user / content / publish_target / review |
| target_id | bigint | - | 对象 ID |
| message | text | - | 操作说明 |
| ip_address | varchar(100) | - | IP |
| created_at | datetime | ✓ | 操作时间 |

典型 action：

```text
login
create_user
update_user
disable_user
create_content
update_content
delete_content
submit_content
approve_content
reject_content
publish_content
republish_content
create_publish_target
update_publish_target
```

建议索引：

```text
INDEX(user_id)
INDEX(action)
INDEX(target_type, target_id)
INDEX(created_at)
```

# 8. 表关系

```text
users
  │
  ├──────────< contents
  │               │
  │               ├──────────< review_records
  │               │
  │               └──────────< publish_records
  │
  ├──────────< review_records
  │
  ├──────────< publish_records
  │
  └──────────< operation_logs

publish_targets
  │
  ├──────────< contents
  │
  └──────────< publish_records
```

# 9. 内容状态示例

## 员工刚创建

```text
review_status = draft
publish_status = unpublished
```

## 员工提交

```text
review_status = pending
publish_status = unpublished
```

## 管理员驳回

```text
review_status = rejected
publish_status = unpublished
reject_reason = "请修改内容"
```

## 管理员审核通过，正在发布

```text
review_status = approved
publish_status = publishing
```

## 发布成功

```text
review_status = approved
publish_status = published
view_url = https://...
published_at = ...
```

## 发布失败

```text
review_status = approved
publish_status = failed
```

管理员可以直接执行“重新发布”，不需要再次审核。

# 11. 推荐数据库

第一阶段建议：

```text
PostgreSQL
```

或：

```text
MySQL
```

均可。

如果没有既有技术限制，更推荐 PostgreSQL，后续需要 JSON 配置、全文检索或扩展字段时会更方便。
