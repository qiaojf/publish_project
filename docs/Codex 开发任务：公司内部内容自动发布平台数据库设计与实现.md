# 一、数据库目标

数据库需要完整支撑以下业务流程：

```text
管理员创建用户
        ↓
普通员工登录
        ↓
创建 / 上传内容
        ↓
保存草稿
        ↓
提交发布
        ↓
管理员审核
   ├───────────┐
   │           │
 驳回         通过
   │           │
   ↓           ↓
员工修改    自动发布
重新提交        ↓
          发布成功 / 失败
               ↓
          员工检索内容
               ↓
          查看发布内容
               ↓
     记录审核 / 发布 / 操作日志
```

数据库必须支持：

1. 用户
2. 内容
3. 发布目标
4. 审核记录
5. 发布记录
6. 操作日志

第一阶段只实现这 6 张核心表。

# 四十八、数据库事务要求

以下操作必须在事务中保证一致性：

```text
创建内容

提交审核

审核通过

审核驳回

管理员直接发布

重新发布

```

例如员工提交：

```text
UPDATE contents.review_status
+
INSERT review_records
+
INSERT operation_logs
```

要么全部成功。

要么全部 rollback。

# 四十九、审核通过事务边界

注意：

真实文件发布可能耗时较长。

不要保持一个数据库事务一直跨越整个文件发布过程。

推荐流程：

### Transaction A

```text
验证状态
↓
review_status = approved
publish_status = publishing
↓
插入 review_record
↓
插入 publish_record(status=publishing)
↓
commit
```

然后执行文件发布。

发布完成：

### Transaction B

成功：

```text
contents.publish_status = published
contents.view_url = ...
contents.published_at = ...

publish_records.status = success
publish_records.publish_url = ...
publish_records.finished_at = ...
```

失败：

```text
contents.publish_status = failed

publish_records.status = failed
publish_records.error_message = ...
publish_records.finished_at = ...
```

这样避免长事务锁住数据库。

# 八十六、最终原则

本项目数据库最重要的原则只有以下几点：

```text

只保留 6 张 MVP 核心表

审核状态与发布状态分离
```
